# Сборка для проверки записи и синхронизации

Это продолжение Phase 1: включена реальная доставка Watch → Phone с durable ACK.
Новые APK называются **WhisperFlow: Neo**, версия **1.1-neo / versionCode 3**.
Репозиторий: https://github.com/svyatoslavpodolskii/whisperflow-neo . Смена названия не меняет applicationId или ключ подписи.
Исходный namespace Wear сохранён, но applicationId обеих платформ теперь `com.pimax.whisperflow`:
это обязательное условие Data Layer. Старое Wear-приложение `com.pimax.whisperflow.wear` может
оставаться установленным рядом. Устанавливать и запускать нужно **WhisperFlow: Neo**.
Данные старой package sandbox автоматически недоступны новой; не удаляйте старое приложение,
если в нём остались нужные записи. Phone и Wear нужно взять из **одного** нового CI run.

## Что происходит

1. Обычный запуск Wear сразу открывает кнопку записи, без вкладок.
2. После разрешения микрофона первое нажатие начинает запись. Есть waveform, таймер и Stop.
3. PCM одновременно записывается в дисковый журнал. На Stop создаются валидный WAV и metadata.
4. «Сохранено» и вибрация подтверждают локальное сохранение, не доставку на телефон.
5. WorkManager публикует Asset `/voice-memory/v1/audio/{UUID}` в системную очередь Data Layer.
   Проверка наличия телефона не блокирует этот шаг; постоянного polling нет.
6. Телефонный listener ставит persistent worker. Worker проверяет UUID, WAV, размер и SHA-256,
   синхронно сохраняет аудио в filesDir, затем фиксирует SQLite inbox transaction.
7. Лишь после этого публикуется persistent ACK с UUID, checksum и целевой watch node.
8. Часы проверяют ACK, помечают запись доставленной и удаляют свой WAV и transport DataItem.
9. Телефон расшифровывает запись отдельной последовательной WorkManager-очередью.
   Ошибка inference не влияет на доставку, не удаляет аудио и доступна для повтора в истории.

ACK тоже является DataItem: временная потеря соединения не теряет его, как могла бы потерять
разовое MessageClient-сообщение. Повторная доставка UUID не создаёт вторую карточку. Удаление
пользователем сохраняет tombstone, чтобы поздний повтор доставки не воскрешал запись.
Операционные ошибки повторяются с exponential backoff и ограничением числа попыток;
аудио после исчерпания попыток остаётся в очереди. Повторный запуск/переподключение/нажатие
счётчика ожидающих повторяет попытку. Опубликованные Assets доставляются самой системой.

## Сети и ADB

ADB используется только для отладки/установки. Он не участвует в передаче записей.
Data Layer работает между **сопряжёнными Android-телефоном и Wear OS часами** через Google Play
services. Одинаковая Wi-Fi-сеть не обязательна: при доступности сети у обоих устройств возможна
доставка через инфраструктуру Google. Без Bluetooth и без доступного интернет-маршрута запись
просто ждёт; сроки доставки определяет система.
[Android Developers](https://developer.android.com/training/wearables/data/overview).

## Что смотреть при одной установке пары APK

- На часах открывается Record, кнопка видна на круглом экране. Старых вкладок нет.
- Сделать две разные записи. Сразу после Stop показывается «Сохранено».
- Без связи: под кнопкой появляется «Ожидают отправки: N»; приложение можно закрыть.
- После восстановления связи: счётчик уменьшается; на телефоне в History появляется раздел
  «Записи с часов», по одной карточке на запись. Файлы можно прослушать до транскрипции.
- LOCAL используется на чистой установке. Модель скачивается один раз через существующие
  настройки телефона; без неё аудио всё равно доставляется, а карточка объясняет необходимость
  загрузки модели и предлагает «Повторить». Существующая настройка GPU/LLM Gateway сохраняется.
- Локальные длинные записи обрабатываются по 30-секундным частям вместо тихого усечения.
- Фоновая обработка сопровождается foreground notification; при низком заряде WorkManager
  откладывает её. Запись уже надёжно находится на телефоне независимо от inference.

Разработка использует debug signing. CI кэширует debug keystore для последующих обновлений;
это не production release key. Проверка APK сверяет applicationId, сертификаты обоих APK и
launcher, а build-identity.txt содержит commit и SHA-256 файлов. APK предыдущего CI run могли
быть подписаны другим временным ключом — не удаляйте приложение с данными ради обхода ошибки
обновления; сначала сохраните нужные записи.

## Что проверяется автоматически

- валидность WAV и отсутствие изменения PCM payload;
- сохранность outbox после пересоздания repository, восстановление orphan metadata и PCM journal;
- отсутствие удаления до корректного ACK, безвредность повторного ACK;
- durable phone file + database reopen, дедупликация и сохранность готового текста при redelivery;
- запрет создания inbox row из повреждённой доставки;
- отсутствие воскрешения удалённой карточки;
- реальный Wear root composable на 192×192 dp round/watch: видимая нажимаемая кнопка записи,
  отсутствие `history`, PNG отрисованного экрана;
- совместимость package identity / signing / launcher в собранных APK.

## Границы доказательства

Локальная проверка 27 октября 2026: `:app:testDebugUnitTest :wear:testDebugUnitTest
:app:assembleDebug :wear:assembleDebug` — успешно. Phone: 30 tests, Wear: 6 tests,
без ошибок. Подписи пары APK сверены. PNG стартового экрана получен native Canvas-отрисовкой
реального measured DecorView в Robolectric и визуально проверен; проверка нажатия и видимости
использует Compose semantics, а не подменённый макет.

Unit/Robolectric tests и сборка не заменяют физическую пару Galaxy Watch 6 + Phone.
Проверка работы GMS между разными сетями, реального микрофона, вибрации, OEM permission UI
и расхода батареи остаётся device test. Принудительная остановка приложения через Android
Settings блокирует фоновые задачи до следующего запуска — это системное поведение.
Дисковый журнал восстанавливается после следующего запуска/события синхронизации; незавершённая
последняя PCM16-пара после аварийного отключения питания может быть отброшена.

Проверены также самые ранние доступные исходники Wear (`4ad8b26`): экрана из двух вкладок
`record/history` в них нет. Точная причина старого установленного экрана без его APK не доказана;
новая сборка имеет проверенный прямой launcher и отдельное имя, чтобы исключить запуск старого APK.

Дополнительный факт: API upstream Releases для v3.0/v2.6/v1.2/v2.5 возвращает только Phone APK
(`whisperflow-debug.apk`, `whisperflow-release.apk`, `WhisperFlow-v*.apk`), без Wear APK.
Поэтому установка Phone APK на часы — конкретная проверяемая гипотеза обрезанного интерфейса.
Теперь Phone MainActivity проверяет FEATURE_WATCH и вместо телефонного layout показывает
понятное требование установить Wear APK. Это защита от неправильного пакета, а не доказательство
того, что пользователь ранее установил именно его.
